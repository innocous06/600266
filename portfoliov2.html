A bit about me

I'm mildly obsessed with the idea that most software has too many dependencies and too little control. So I started building the layer underneath — the networking, the databases, the parts nobody thinks about until they break.

I like problems where "it works" isn't the finish line — where you also need to know why it works, what happens when the network lies to you, or what breaks first under load. That's led me down a lot of rabbit holes: kernel-level packet tunneling, on-device ML, and enough small self-hosted tools that I've basically become my own IT department.

If it involves networking, databases, or an excuse to avoid a dependency, I've probably already built it — right alongside an unreasonable number of small tools nobody asked for.

That said, code is the part of my life I happen to be good at, not the whole of it. I build things because it's genuinely fun, not because I'm chasing a personality around a GitHub graph. Based in the Himalayas, which does wonders for perspective when your code doesn't compile.
